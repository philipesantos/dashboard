## Overview

This file is the only source of the dashboard host's look. The app's theme
(`app/src/theme.generated.css`) and the styling widget content can select
(`design/widget-map.generated.json`) are generated from it by `pnpm --filter ./design gen`, and
`pnpm --filter ./design check` fails in CI when either drifts, when a pairing below falls under
WCAG AA, or when widget content could reach a surface only the host draws.

The direction is **Ardósia + Musgo**: cool slate neutrals around hue 250, one cobalt accent,
Bricolage Grotesque for headings, Figtree for text and IBM Plex Mono for ids and domains. It is
calm on purpose. The dashboard shows other people's data from plugins, so the host stays quiet
and lets content carry the color.

Two kinds of things are drawn:

- **Host surfaces**, which only the host draws: the chrome, each widget's frame with the
  plugin's name and icon, host dialogs with their scrim, anything raised above a frame, and the
  focus style. Their roles are host-only.
- **Widget content**, the declarative UI a plugin returns. It selects a tone and a component
  variant, never a color, and every tone and variant resolves to shared roles only.

What tells a host dialog apart is its form, not a color: it covers the chrome and every frame,
the rest of the window goes inert, and it holds focus. See `docs/design/host-surfaces.md`.

## Colors

Every role has a light value under its name and a dark value under `<name>-dark`. Values are
`oklch()`, so lightness and hue read directly. Neutrals sit at hue 250 to 255 with very low
chroma; the accent is cobalt at hue 235 to 245.

### Surfaces and text

- **background**: the window behind everything. Near-white in light, deep slate in dark.
- **foreground**: body text on `background`. Near-black slate, so text keeps the hue of the
  surfaces.
- **card**: panels inside a widget or a page. Pure white in light, one step above `background`
  in dark, so a panel reads as lifted without a shadow.
- **card-foreground**: text on `card`, the same as `foreground`.
- **popover**: menus and popovers. The same as `card`; elevation separates them.
- **popover-foreground**: text on `popover`.

### Actions and emphasis

- **primary**: the cobalt accent: the main button, the selected item, links. Shared, so widget
  content can use the accent tone. The primary button's hover draws it at 90% rather than
  shadcn's 80%, where `primary-foreground` measured 3.80 on `background`; at 90% it holds
  4.62.
- **primary-foreground**: text and icons on `primary`.
- **secondary**: the quiet button's fill, a light slate.
- **secondary-foreground**: text on `secondary`.
- **muted**: quiet fills such as a table's hover row.
- **muted-foreground**: secondary text such as descriptions and captions, 4.83:1 on `muted` in
  light, its closest pairing.
- **accent**: the hover and focus fill of menu items, a pale cobalt.
- **accent-foreground**: text on `accent`, a dark cobalt.

### Status

Status is never shown by color alone: the host draws an icon beside each status tone.

- **destructive**: errors and destructive actions, a warm red. The destructive button draws it
  as text on a soft fill of itself: /10 at rest and /20 on hover in light, /20 and /25 in dark.
  The starting theme's oklch(0.56 0.2 27) measured 3.67 on the light hover over `background`,
  so light is darker now. In dark, the hover moved from shadcn's /30, where the starting
  oklch(0.7 0.18 22) measured 3.80, to /25, and the value is lighter, holding 4.61.
- **ok**: success, a green at hue 150 that holds 4.5:1 as text in both themes.
- **warning**: caution, an amber at hue 65 to 80 dark enough to read as text in light.

### Edges

- **border**: card edges and dividers. Light by design.
- **input**: the edge of text fields, selects and switches, and in dark mode their fill. It is
  the only thing that marks a field, so it holds 3:1 against every surface (WCAG 1.4.11): 3.94
  on `card` in light. The starting theme's near-white edge measured 1.43. In dark it stays
  translucent, at 35% white instead of 14%, so field fills built from it (`input`/30, /50) also
  lighten a little.
- **ring**: the host's focus style, drawn on every control including widget content's. Drawn
  solid: at shadcn's 50% it measured 1.79 on `background`, below the 3:1 a focus indicator
  needs.

### Data

- **chart-1**: the first data series, the accent's hue.
- **chart-2**: the second series, a teal. Darker in light than the starting oklch(0.68 0.1 200),
  which measured 2.76 on `card`; a mark that carries data needs 3:1.
- **chart-3**: the third series, an amber, moved toward orange and darkened from
  oklch(0.74 0.13 80), which measured 2.34 on `card`.
- **chart-4**: the fourth series, a violet.
- **chart-5**: the fifth series, a coral.

### The chrome

The app's chrome uses the sidebar roles. They start equal to their shared counterparts and are
kept separate so the chrome can change without moving widget content.

- **sidebar**: the chrome's surface.
- **sidebar-foreground**: text in the chrome.
- **sidebar-primary**: the selected item in the chrome.
- **sidebar-primary-foreground**: text on `sidebar-primary`.
- **sidebar-accent**: hover in the chrome.
- **sidebar-accent-foreground**: text on `sidebar-accent`.
- **sidebar-border**: the chrome's dividers.
- **sidebar-ring**: focus in the chrome.

### The widget frame

- **frame**: the frame's body, where widget content is drawn.
- **frame-foreground**: text the host draws in the body, such as an error.
- **frame-border**: the frame's edge.
- **frame-header**: the frame's header, which holds the plugin's name and icon, a step away from
  `frame`. What makes the header the host's is its place, above the body that widget content
  cannot leave and always showing the manifest's name, not this color, which shared roles come
  close to.
- **frame-header-foreground**: the plugin's name in the header.

### Host dialogs

- **dialog**: the dialog's surface.
- **dialog-foreground**: text in a dialog.
- **scrim**: the layer between a dialog and the rest of the window.

### What only the host draws

The chrome (`sidebar*`), the frame (`frame*`), host dialogs (`dialog*` and `scrim`) and the focus
style (`ring`) are host-only: no tone or variant of widget content may resolve to them, and
`check` fails if one does. The split is by role, not by color. `sidebar-primary` holds the same
value as `primary`, and widget content may use the accent; what tells a host surface apart is its
place and, for a dialog, its form, never a color no widget can reach.

```design-rules
hostOnly:
  - sidebar
  - frame
  - dialog
  - scrim
  - ring
```

fills drawn over it, as a hover state or a soft badge. The app's components may draw a role only

## Typography

The three families are bundled with the app by `@fontsource` packages, so nothing loads from
the network. Each is under the SIL Open Font License 1.1, which allows shipping it in an
Apache-2.0 app as long as the license travels with it; the texts ship in
`app/public/licenses/fonts/`.

- **heading**: Bricolage Grotesque, weight 600, for titles. Its optical size axis keeps large
  titles tight and small ones open.
- **body-xs**: Figtree at 0.75rem, for badges and fine print.
- **body-sm**: Figtree at 0.875rem, the default size of controls and table text.
- **body-base**: Figtree at 1rem, for running text.
- **body-lg**: Figtree at 1.125rem, for lead text.
- **body-xl**: Figtree at 1.25rem, for section titles.
- **body-2xl**: Figtree at 1.5rem, for page titles.
- **mono**: IBM Plex Mono, for plugin ids, domains and other values the person compares
  character by character.

The body sizes and line heights equal Tailwind's `text-xs` to `text-2xl`, so moving the theme
here changed nothing on screen.

## Layout

- **unit**: 0.25rem, Tailwind's `--spacing`. Every padding, margin and gap is a multiple of it,
  so changing it rescales the whole app.
- **control-gap**: two units, between a control's icon and label and between list items.
- **frame-padding**: four units, inside a widget frame's body.
- **grid-gap**: four units, between frames on the dashboard grid.

## Elevation & Depth

Depth is mostly carried by surface lightness. Shadows are reserved for what floats, and every
level above `flat` is the host's: widget content cannot raise anything above its frame.

- **flat**: widget content and everything inside a frame. No shadow.
- **frame**: the widget frame on the dashboard grid, Tailwind's `shadow-sm`, just enough to lift
  it off `background`.
- **raised**: the host's menus, selects and popovers, Tailwind's `shadow-md`. The demo's submenu
  used `shadow-lg`; it now draws this level, like the menu it opens from.
- **dialog**: host dialogs above the scrim, Tailwind's `shadow-lg`, the deepest level.

The levels start at Tailwind's values so moving them here changed nothing on screen. The active
tab's slight lift is a control's detail, not a level, and keeps Tailwind's `shadow-sm`.

```design-rules
elevation:
  flat: { shadow: none, dark: none }
  frame:
    shadow: "0 1px 3px 0 rgb(0 0 0 / 0.1), 0 1px 2px -1px rgb(0 0 0 / 0.1)"
    dark: "0 1px 3px 0 rgb(0 0 0 / 0.1), 0 1px 2px -1px rgb(0 0 0 / 0.1)"
    hostOnly: true
  raised:
    shadow: "0 4px 6px -1px rgb(0 0 0 / 0.1), 0 2px 4px -2px rgb(0 0 0 / 0.1)"
```

## Shapes

- **base**: 0.625rem, shadcn's `--radius`. The steps `sm` to `4xl` derive from it with the
  multipliers 0.6, 0.8, 1, 1.4, 1.8, 2.2 and 2.6, so one change moves every corner.

## Components

Widget content is built from six components: text, list, table, chart, button and simple form.
It selects a tone and a variant, never a color, a font, a size or a class. Each entry below has a
`-dark` twin that references the dark roles, so the format's own checker sees both themes.

### Text

- **text-default**: body text in the widget, `foreground` at the default size.
- **text-muted**: secondary text, `muted-foreground`.
- **text-heading**: a title inside the widget, in the heading face.

### List and table

- **list-default**: list items, `foreground`, separated by `control-gap`.
- **table-header**: column headers, `muted-foreground`, so the data reads first.
- **table-row**: table cells, `foreground`.

### Chart

- **chart-default**: axes and labels, `muted-foreground` at the smallest size. Series take
  `chart-1` to `chart-5` in order; a widget cannot pick a series color.

### Button

Every button shows the host's focus ring, which no variant can change.

- **button-primary**: the one main action, cobalt.
- **button-secondary**: other actions, a quiet slate fill.
- **button-outline**: an action beside a primary one, outlined with `input`.
- **button-ghost**: a low-emphasis action with no fill until hover.
- **button-destructive**: an action that deletes or undoes, red text on a faint red fill.

### Simple form

The form has no password or masked field.

- **form-input**: a text field, edged with `input` so it is found without its label.
- **form-label**: a field's label.

### Tones and variants

A tone colors text: `default`, `muted`, `accent`, and the three statuses `ok`, `warning` and
`error`, each drawn with its icon from the app's lucide set. A name the host does not know draws
as `default`, and the host records it in the plugin's log. A variant is one of the entries above,
named `component.variant`; `rounded` names a step derived from **base**, and `spacing` and
`typography` name tokens. The generator writes these, with role names only, to
`design/widget-map.generated.json`, the only styling the declarative UI kit can reach.

```design-rules
tones:
  default: { text: foreground }
  muted: { text: muted-foreground }
  accent: { text: primary }
  ok: { text: ok, icon: circle-check }
  warning: { text: warning, icon: triangle-alert }
  error: { text: destructive, icon: circle-x }
unknownTone: default
variants:
  text.default: { text: foreground, typography: body-sm }
  text.muted: { text: muted-foreground, typography: body-sm }
  text.heading: { text: foreground, typography: heading }
  list.default: { text: foreground, border: border, spacing: control-gap, typography: body-sm }
  table.header: { text: muted-foreground, typography: body-sm }
  table.row: { text: foreground, border: border, typography: body-sm }
  chart.default: { text: muted-foreground, typography: body-xs }
  button.primary: { text: primary-foreground, fill: primary, rounded: lg, spacing: control-gap, typography: body-sm }
  button.secondary: { text: secondary-foreground, fill: secondary, rounded: lg, spacing: control-gap, typography: body-sm }
  button.outline: { text: foreground, fill: background, border: input, rounded: lg, spacing: control-gap, typography: body-sm }
  button.ghost: { text: foreground, rounded: lg, spacing: control-gap, typography: body-sm }
  button.destructive: { text: destructive, fill: destructive/10, rounded: lg, spacing: control-gap, typography: body-sm }
  form.input: { text: foreground, fill: background, border: input, rounded: lg, typography: body-sm }
  form.label: { text: foreground, typography: body-sm }
```

## Do's and Don'ts

- Do edit this file and run `pnpm --filter ./design gen`; never edit the generated theme.
- Do keep every pairing at WCAG AA in both themes; the check measures them.
- Don't show a status by color alone.
- Don't give widget content a way to reach a host-only role.
